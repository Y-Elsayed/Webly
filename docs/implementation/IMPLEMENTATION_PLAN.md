# Executable R0 + R1 implementation plan

Task IDs are stable. `REQUIREMENTS_AUDIT.md` maps every requirement; `ARCHITECTURE_DECISIONS.md` defines contracts. Order below is dependency order, with vertical release slices. Implement only after this planning turn. Complexity is relative (S ≤2 days, M ~3–5 days, L ~1–2 weeks, XL multiple weeks), not a delivery estimate. Each task is independently executable after its dependencies unless marked **external**. A task is done only when its cited acceptance evidence and verification command/procedure are recorded in `PROGRESS.md`. Keep local `build_pipelines`, Streamlit and file repository functioning via adapters; hosted schema never silently changes existing local paths.

## Target workflow contracts

The notation `actor → owner: contract [states]; failure; telemetry` describes the durable boundary. All tenant-owned DB rows carry tenant ID and project-owned rows carry project ID; auth context is server derived. Every mutating API accepts or derives an idempotency key and writes audit/outbox in the same transaction. Human approvals name an actor and source/version.

1. **Onboarding/source approval.** Owner/admin → admin API: create workspace/project with purpose, languages, timezone, approved domains, origins, owner and policy; `draft → configured`. Admin records authority to crawl and source scope/version; `proposed → previewed → approved/rejected`. Editor may propose; only admin publishes approval. Duplicate create key returns same project; invalid scope creates no job. Audit actor/scope/time; UI shows approval and exclusions. DB owns project/source; object store owns no authority.
2. **Crawl preview/ingestion jobs.** Admin → API: `POST ingest` with scope and idempotency key returns 202/job ID. DB job row: `queued → validating → crawling → extracting → embedding → building → validating_snapshot → awaiting_approval → published`, or `failed/cancelled/completed_no_change`. Worker claims one per-project lease; checkpoint/retry is idempotent by job ID and content hash. Preview crawl stops before indexing and records discovered/excluded/failed pages with reasons. Every URL/redirect/robots request passes network policy; fetch error does not imply deletion. Cancellation is cooperative at checkpoint. Job API and UI show progress, errors, lease age, next retry; alert on stuck/critical source failure.
3. **Extraction/build/publication/rollback.** Worker persists immutable HTML/page-version evidence and structured sections/segments/edges, embeds with bounded batch/retries, writes FAISS+lexical artifacts and manifest, validates bijection/embedding contract/coverage/critical facts. Draft `building → ready/failed`; admin preview/evaluation approves; compare-and-set active pointer changes `ready → published`, old stays retained. A failed CAS or artifact check never changes active pointer. Queries pin version; rollback uses same CAS and revalidates time-sensitive fact policy. Snapshot checksum, counts, build times, publication actor and rollback reason are logged.
4. **Widget session/query.** Browser → widget API: project public key + origin/rate checks yields scoped short token; `issued → expired/revoked`. Query with session and idempotency key validates input, pause, quota, then records request `accepted/reserved → running → response_committed → delivered/delivery_uncertain` or `failed/refunded`. Server pins snapshot/prompt/policy before retrieval. Retry returns same result. On technical failure/paused/exhausted project, widget shows contact route without model spend or success claim. UI handles keyboard, loading/error, citations and RTL only if enabled. Server logs request ID, not raw visitor text in general logs.
5. **Retrieval/answer.** Router chooses new/follow-up/transform/unsupported; parsed JSON schema failures choose deterministic search. Pinned snapshot services search semantic+lexical, merge by segment ID, filter validity/approval, select complementary original spans, and optionally do one bounded follow-up. Planner can search/drop/clarify/finish only within validated IDs, limits and deadline. Critical facts resolve exact approved scope; conflicts/expiry force clarification/fallback and review issue. Generation returns structured status/citations; validator checks schema, membership/span and fact rules, repairs once or falls back. Trace records step IDs, ranks, selected evidence, action reasons, token/cost/timing but restricted text retention. Provider timeout ends within deadline.
6. **Feedback/contact.** Visitor token + turn binds one replaceable rating and optional reason; audit records replacements. Contact requires explicit fields/purpose/consent; `submitted → pending_delivery → delivered/failed → contacted/closed` are distinct. DB restricted contact row and delivery outbox are authoritative. Duplicate submission/delivery keys reuse lead; bounded retry and failure inbox exist. Widget confirms server acceptance, never promises live staff. Analyst sees redacted review; support sees assigned leads only. Delivery lag/failure alert has named owner.
7. **Correction/regression/republish.** Feedback/fallback or source failure creates review issue `open → triaged → correction_proposed → tested → published/closed` with category from spec §6.6. Editor links approved source span or structured fact, stages a new version, runs fixed regression questions, admin publishes with CAS. No LLM-generated correction auto-publishes. Track before/after version and recurrence denominators; rollback on regression. UI links issue, source, test and publication.
8. **Analytics/dashboard/review.** API/worker domain transaction → outbox → deduplicating processor → raw event + affected day aggregates; `pending → processed/retry/dead_letter`. Browser events are optional untrusted observations. Event UTC time determines project-local reporting day; late event recomputes day; watermark exposes lag. Customer UI shows definitions/numerators/denominators, filters, conversations, source status and manual review groups; ops UI shows cost/error/queue/lag. Zero denominator says “not enough data.” Restricted transcript/contact authorization is separate from aggregate permission. Replays are idempotent.
9. **Usage.** API transaction reserves one unit per accepted unique visitor request with period/pricing version and row lock. Commit response and finalize once at delivery boundary; on precommit failure refund; uncertain delivery is explicit and reconciled. Sweeper reconciles stale reservations with durable response record, never with browser click. Duplicate retry cannot reserve again. Cost attempts remain recorded even when unit refunded. Usage UI shows available, reserved, charged, uncertain, reset date, warning; quota exhaustion yields contact fallback. Ledger and event counts reconcile daily, billing independent of analytics processing.
10. **Retention/deletion/backup/recovery.** Policy scheduler marks expired transcript/trace/contact data; authorized delete writes tombstone and removes retained text and derived review excerpts/exports. Snapshots retain according to approved source/version policy; active/pinned versions cannot be collected. DB/object backups encrypted with expiry; restore into isolated environment, replay deletion tombstones, verify checksums, then enable serving. Export is role scoped and audited. Retention job/delivery/recovery failures page named operator.

## Release criteria

R0 is complete when T00–T03 pass deterministic real-FAISS tests, immutable publication/crash/pin tests, original-evidence/citation contract tests, and the local workflow still runs. R1 engineering is complete when T04–T15 pass DB/vector/concurrency/security/browser/recovery suites and the documented local stack starts from empty volumes. Managed launch additionally requires T16 and human corpus/customer approvals. Passing mocks alone is never a quality or capacity claim.
